## 3. Technology Stack & Architecture
*   **Frontend**: React 18 (Vite), TailwindCSS (v4), TypeScript, React Router DOM, React Query (TanStack Query v5) for all API data fetching and cache invalidation. Icons are from `lucide-react`.
*   **Backend**: Node.js, Express.js (TypeScript compiled via `tsc`).
*   **Database**: MongoDB (Atlas) modeled and migrated exclusively using **Prisma ORM**.
*   **Security & Validation**: Stateless JWT authentication via HTTP headers. All API request bodies are validated using `zod` schemas in Express middleware before hitting controllers. Passwords and PINs are hashed using `bcryptjs`. Sensitive data like `cvv` and `cardNumber` are hashed in the database as `cvvHash` and `cardNumberHash`.

## 4. Core Features & Workflows (Start to End)

### A. Advanced Virtual & Burner Cards
*   **Standard Virtual Cards**: Permanent cards for online spending.
*   **Burner Cards**: The user generates a card with a specific `dailyLimit`, an `expiresAt` duration (e.g., 24h), and an optional `merchantLocked` string. In the UI (`BurnerCardsSection.tsx`), the card number is masked. The user can click "Reveal" to see the full 16 digits, CVV, and EXP. If the user clicks "Burn Now", a `PATCH /api/cards/:id` call is made setting the status to `CANCELLED`. React Query invalidates the cache, and the card instantly disappears from the active UI.
*   **Family/Child Cards**: Premium users can issue sub-cards to dependents, monitor their transactions, approve/deny money requests, and enforce strict spending controls.

### B. Emergency Protocol (The "Panic Button")
*   Designed to protect users from physical coercion (e.g., "$5 wrench attacks").
*   The user configures a "Ghost Wallet" and a secondary PIN in `RecoverySetup.tsx`.
*   If the Panic Button is triggered, a global database update sets `isFrozen = true` and `status = 'FROZEN'` across all of the user's Accounts and Cards. 
*   The main UI hides the true net worth and only displays the low-balance Ghost Wallet (e.g., $150) to satisfy the attacker. 

### C. Dynamic QR & UPI Payments Engine
*   Located in `PaymentsPage.tsx`.
*   **Receiving**: When a user types an amount to receive, it triggers a debounced `POST /api/transactions/qr-intent` call. This generates a `QrIntent` document in MongoDB with a unique ID, the user's VPA, and the exact amount. 
*   **Scanning**: The user clicks "Mock Scan", which hits `GET /api/transactions/qr-intent/scan`. The backend queries MongoDB for the most recent active intent, returning the VPA and amount, which instantly populates the transfer form in the UI. 

### D. AI Wealth & Auto-Trader
*   Abstracted algorithmic trading interface. Instead of complex candlestick charts, users deposit funds and the AI automatically allocates them across Stablecoins, Blue-chip Crypto (BTC/ETH), and High-Yield Savings based on a selected Risk Profile (Conservative, Balanced, Aggressive).

*   **RecoveryProfile**: `id`, `userId`, `aliasUrl`, `hashedPin`, `emergencyAccId`, `isActive`.

## 7. Representative Code Snippets

### A. Prisma Schema (Card Model)
```prisma
model Card {
  id              String    @id @default(auto()) @map("_id") @db.ObjectId
  userId          String    @db.ObjectId @map("user_id")
  accountId       String    @db.ObjectId @map("account_id")
  cardNumber      String    @unique @map("card_number") // Masked display
  cardNumberHash  String    @map("card_number_hash") // SHA-256 of full number
  last4           String    @map("last_4")
  expiryMonth     Int       @map("expiry_month")
  expiryYear      Int       @map("expiry_year")
  cvvHash         String    @map("cvv_hash") // bcrypt hash
  cardType        String    @default("VIRTUAL_DEBIT") @map("card_type")
  dailyLimit      Float     @default(50000) @map("daily_limit")
  isFrozen        Boolean   @default(false) @map("is_frozen")
  isOnlineEnabled Boolean   @default(true) @map("is_online_enabled")
  isContactless   Boolean   @default(true) @map("is_contactless")
  status          String    @default("ACTIVE") // ACTIVE | BLOCKED | EXPIRED | CANCELLED
  expiresAt       DateTime? @map("expires_at")
  merchantLocked  String?   @map("merchant_locked")

  account Account @relation(fields: [accountId], references: [id])
  user    User    @relation(fields: [userId], references: [id])

  @@map("cards")
}
```

### B. Frontend API Interceptor (`src/services/api.ts`)
```typescript
import axios from 'axios';

const api = axios.create({
  baseURL: import.meta.env.VITE_API_URL || 'http://localhost:3000/api',
});

// Automatically inject JWT token into all requests
api.interceptors.request.use((config) => {
  const token = localStorage.getItem('token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});
```

### C. Frontend React Component (React Query & Tailwind)
```tsx
import { useMutation, useQueryClient } from '@tanstack/react-query';
import { api } from '@/services/api';

export function BurnerCardGenerator() {
  const queryClient = useQueryClient();
  const mutation = useMutation({
    mutationFn: (limit: number) => api.post('/cards/burner', { limit, durationHours: 24 }),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ['cards'] }),
  });

  return (
    <button 
      onClick={() => mutation.mutate(50)}
      className="bg-blue-600 hover:bg-blue-700 text-white px-4 py-2 rounded-md border border-zinc-700"
    >
      Generate $50 Burner
    </button>
  );
}
```

import { Request, Response } from 'express';
import { z } from 'zod';

const burnerSchema = z.object({ limit: z.number().positive(), durationHours: z.number() });

export const createBurner = async (req: Request, res: Response) => {
  const parsed = burnerSchema.parse(req.body);
  const card = await prisma.card.create({
    data: {
      userId: req.user!.id,
      cardType: 'BURNER',
      dailyLimit: parsed.limit,
      // ... cryptographic hashing logic omitted for brevity
    }
  });
  res.json({ card });
};
